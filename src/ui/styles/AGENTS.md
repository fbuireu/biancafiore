# src/ui/styles

The global cascade. Everything here is cross-cutting; per-component styling lives beside its component in `@modules/*`.

## Layer order

Declared once, in [`index.css`](./index.css):

```css
@layer reset, vendor, overrides, base, theme, global, modifiers, animations;
```

Cascade correctness depends on this order. Every file opens by naming its slot and nothing else (an `@layer` block, or `layer()` on the `@import` for [`vendor.css`](./vendor/vendor.css), which only pulls in the cookie-consent package stylesheet), and no file re-declares the order:

| Folder / file | Layer |
| --- | --- |
| [`reset/reset.css`](./reset/reset.css) | `reset` |
| `vendor/vendor.css` | `vendor` |
| [`vendor/cookie-consent.css`](./vendor/cookie-consent.css) | `overrides.cookie-consent` (nested sub-layer) |
| [`base/base.css`](./base/base.css) | `base` |
| [`global/variables.css`](./global/variables.css) | `theme` |
| [`global/global.css`](./global/global.css), [`reveal.css`](./global/reveal.css), [`slider.css`](./global/slider.css) | `global` |
| [`global/modifiers.css`](./global/modifiers.css) | `modifiers` |
| [`global/animations.css`](./global/animations.css) | `animations` |

`overrides` has no stylesheet of its own: it is the parent of the cookie banner's sub-layer, so the banner's rules beat the package's and lose to everything from `base` on. New files are wired through the folder's `index.css`, which `index.css` imports in layer order.

## Tokens (`global/variables.css`)

- **Colour**: an oklch base per family (`--primary-main`, `--neutral-main`) with light/dark steps derived via `color-mix`. Colour literals live in `variables.css`, and every other stylesheet, the vendor's `--cc-*` assignments in `vendor/cookie-consent.css` included, reads a token: the dialog's scrim is `--scrim`, 90% black on both themes because `--black` flips to white in the dark one. The semantic tokens are the `light-dark()` pairs, and they are exactly `--ink`, `--ink-soft`, `--muted`, `--faint`, `--line`, `--line-soft`, `--gold`, `--gold-bright` and `--surface`. Every one of them is censused here, so adding another means editing this line. The spacing, type and layout tokens are `@property`-registered and the colour tokens are not, which the docs test holds: a registered colour stops falling back through the theme when unset, and a theme switch would interpolate it instead of flipping. See ADR 0005 / 0008.
- **Type scale**: fully derived. `--ratio: 1.25` builds the `-min` ladder, per-level `--font-growth-*` builds `-max`, and each `--font-size-*` is a `clamp()` between the two across `--vw-min`/`--vw-max`, wrapped in `round(nearest, …, --round-interval)` for baseline snapping, consumed as `var(--font-size-h1…h6 | sm | xs)`. Two kinds of `font-size` escape the ladder:
	- **Container-scaled:** the ladder is viewport-driven, so type that has to scale with its *container* opts out with a `cqi` `clamp()` instead. `.editorial-section-title` does it in `global.css`, and under `@modules` the components taking it are `aboutIntro`, `cities`, `columnsToggle`, `contactForm`, `contactIntro`, `errorLayer`, `form`, `input`, `menu`, `menuButton`, `projectList`, `projectSection`, `projectsIntro`, `testimonialsSlider`, `textarea` and `welcome`. That list is a census: a `cqi` clamp in a further component means adding it here.
	- **Neither:** some `font-size` declarations under `@modules` are neither on the ladder nor container-scaled, and they sit in `errorLayer` (both on `.error-layer__ghost`, `44vw` dropping to `60vw` below 640px). They scale *inversely*: the decorative glyph takes a larger share of a narrower screen, which a `clamp()` growing with the available width cannot express. The docs test pins those values and the folder, so a declaration added, removed or retuned fails until this sentence names it.
- **Rhythm**: `--leading`, `--leading-heading`, `--leading-display`, `--rhythm`.
- **Spacing**: a `--space-3xs…3xl` ramp of viewport clamps.
- **Layout**: `--header-height` and a `--grid-*` set of named measures (`--grid-article`, `--grid-narrow`, `--grid-text`, `--grid-content`, `--grid-sidebar`, plus breakpoint-shaped ones). They are widths, not breakpoints: every use sizes a box or a grid track, never a query condition, because a container query cannot read a custom property in its condition. Each measure is declared twice (once in `:root` and once as an `@property`), which is exactly how a dead one hides, so the docs test rejects any `--grid-*` nothing consumes.

## Colour scheme

`:root` is `color-scheme: light`; dark comes from `[data-theme="dark"]`, set before first paint by the bootstrap [`core/components/head/Head.astro`](../modules/core/components/head/Head.astro) renders from [`themeToggle/utils/preference.ts`](../modules/core/components/themeToggle/utils/preference.ts), with `prefers-color-scheme` as the fallback whenever the reader has chosen nothing; only a click on the toggle is persisted. Sections that invert against the page mix in the `inverted-color-scheme` block, which flips in both directions; the components that do are `blog`, `blogPreview`, `footer` and `relatedArticles`. The mix is a runtime contract as well as paint: `backgroundObserver` in [`header/utils/interactions.ts`](../modules/core/components/header/utils/interactions.ts) observes every `.inverted-color-scheme` on the page and inverts the logo and menu button while the sticky header's midline sits over one. So the header names no section's block class of its own, and a new inverting section needs no edit there.

That nested inversion is exactly what breaks when lightningcss downlevels `light-dark()` into an inherited-var polyfill; hence `Features.LightDark` in `lightningcss.exclude` in [`astro.config.ts`](../../../astro.config.ts). Don't remove it; dev looks fine and prod doesn't. See ADR 0006.

## Conventions

- **BEM throughout** (ADR 0014), and the docs test holds the modifier syntax: fused onto their block (`.theme-toggle--toggled`, `.reveal--fade`), never standalone `.--modifier` classes and never `is-`/`has-` state classes. A modifier also never floats free of its block: `.columns-toggle__label--single` exists with no rules on `.columns-toggle__label` at all, but the markup still carries both, and the docs test rejects a modifier whose block appears nowhere. The one stylesheet exempt from all of this is `vendor/cookie-consent.css`, whose selectors (`.pm__section--expandable.is-expanded`) are vanilla-cookieconsent's DOM and not ours to rename.
- **The utility files are split by layer, not by kind.** Both hold blocks meant to be *mixed* onto a component: behaviour that has to beat component CSS by layer is in `global/modifiers.css` (`@layer modifiers`, censused under [Mixed-in utilities](#mixed-in-utilities)), the typographic and layout vocabulary in `global.css` (`@layer global`, listed below). Component stylesheets are unlayered and beat both, so a component can always override a mix for itself.
- **The `page` block** sits on `<html>` ([`BaseLayout.astro`](../modules/core/components/baseLayout/BaseLayout.astro)), with `<main>` as `page__main`. It carries two things: the route (`page--home`, `page--article`…) and page-wide state (`page--menu-open`, toggled by `header/utils/interactions.ts`), which the blocks it restyles consume by descent.
- **Page containers**: `base.css` names a container on `html.page--<route>` as `<route>-page` (`home-page`, `article-page`, `tags-page`…), always with `inline-size scroll-state`. The naming is mechanical, so the only interesting facts are the routes that get *no* container: `tag`, `404` and `500`. There is deliberately no `page--tag`: `getPage` resolves `/tags/<slug>` to `tags`, because `PAGES_ROUTES.TAGS` is declared before `TAG` and `getPage` takes the first key `isWithin` matches, which counts a route as containing everything under it, so tag detail pages share the `tags-page` container. `/articles/<slug>` goes the other way, to `article`, only because `ARTICLE` is declared before `ARTICLES`: the order of that object is the whole of the rule. If you ever want them separated, reorder `PAGES_ROUTES` first and expect [`_tag.css`](../../pages/tags/_tag.css) to need updating. `404` and `500` get none because `errorLayer` sizes itself off the viewport rather than off a container.
- **`global.css` utilities.** The editorial set (`.editorial-eyebrow`, `.editorial-kicker`, `.editorial-section-title`, `.editorial-headline`, `.editorial-meta`, `.editorial-cta`) is the canonical typographic vocabulary. Beside it live `.common-wrapper` (the max-width centring wrapper), `.stretch-arrow` (the CTA arrow whose `d` morphs on hover), `.arrow-box` (the box an arrow waits in until its trigger reveals it, next bullet), the font switches `.font-serif` / `.font-sans-serif`, a small atomic layer (`.grid`, `.flex`, `.relative`, `.row-wrap`, `.row-balance`, `.column-wrap`, `.column-nowrap`, `.justify-flex-start`, `.justify-flex-end`, `.justify-center`, `.align-center`, `.align-baseline`) and `.section-title`, which is the one block here that is *not* canonical (next bullet). A utility an element's own block already settles is dead there: a component stylesheet is unlayered and beats it, so `flex` beside a block that sets `display: grid`, or `align-center` beside one that sets `display: block`, applies nothing. The docs test rejects an atomic utility, a class whose rule holds declarations only, every property of which its element's own block settles or makes inert. This list is the census: every block `global.css` declares is named here, and adding one without naming it fails the docs test. So does declaring one nothing uses: every block above has at least one call site, and some of those sites are not markup, so grep the whole of `src` before calling one dead (`.align-baseline` looks unused until you find it in the heading HTML `renderArticleContent` emits, in `@application/dto/article/utils/content.ts`).
- **The stretch arrow's path has one source.** `svg/stretch-arrow.svg` holds its rest shape. The Astro components inline the file, and `StretchArrow.tsx` reads its paths from it for the React ones, so no path is typed twice. `variables.css` holds only the hover shape, as `--stretch-arrow-shaft-hover` and `--stretch-arrow-tip-hover`, and each token keeps the path commands of the rest path it replaces, because a `d` only morphs between paths of one shape and otherwise flips. The docs test compares the commands. The morph itself is written once, as a style query in `global.css`: a trigger declares `--stretch-arrow: hover` in its hover state and the arrows beneath it take the hover shape. That is what lets the Article card say it on the `~ .article-card__item` rule its link triggers, which a class mixed onto the hovering element could not reach, and it leaves each trigger its own condition (`:hover` alone, or `:hover` and `:focus-visible`). The box an arrow waits in until a hover reveals it is written once too, as `.arrow-box` in `global.css`, which the Article card's arrow and the 404 page's links mix in: it holds the arrow at `opacity: 0` and `translate: -6px 0`, with `transition: opacity 0.35s ease, translate 0.35s cubic-bezier(0.2, 0.7, 0.2, 1)`. Its trigger reveals it from the rule that declares `--stretch-arrow: hover`, writing `opacity: 1` and `translate: 0 0` on the element's own class, which also places the box (`vertical-align` in the card's title, `align-self` in the 404 link). The docs test rejects any other `opacity`, `translate` or `transition` on an element that inlines the stretch arrow, in every stylesheet but `global.css`.
- **An svg a stylesheet draws is a mask painted with `currentColor`, never a background.** The file's own `fill` ignores the theme: `chevron-down.svg` is black, which the dark theme hides, so `table-of-contents.css` draws it as a `mask` over `background-color: currentColor` and the chevron takes the colour of the text beside it. The docs test rejects a `background` that takes an svg url and a `mask` that no `currentColor` paints.
- **`slider.css` declares the slider's default ramp**: one slide with no gap, then two with a `2rem` gap from 720px, on `.slider-wrapper`. It sits in the `global` layer, so a placement's unlayered rule beats it whatever the stylesheet order. A placement states only the steps that differ from the slider's default ramp, and the docs test rejects one that restates a step the default already says. `TestimonialsSlider` sets its own `--slides-per-view` and `--slider-gap` on `.slider__track`, below the wrapper, so the ramp never reaches its slides.
- **There is more than one section-title vocabulary, and `.editorial-section-title` is the canonical one.** `.section-title` (letter-spacing, uppercase, centred; it sets no family, size or colour) and `.editorial-section-title` (display family, a `cqi` clamp, `--ink`, baseline-snapped leading) do not render alike. `.section-title` survives only because collapsing the two is a visual change to every component still on it, and those are `blogPreview`, `relatedArticles` and contact's `tabs` (the last of which dresses an `h4` in a tab strip that the display treatment would visibly break). That list is the whole of it and the docs test censuses it, so it can only shrink: retire one by moving its markup to `.editorial-section-title` and striking it from that sentence, and when the sentence empties, delete `.section-title` from `global.css`.
- `reveal.css` holds the scroll-driven reveals, in two mechanisms (ADR 0007). `.reveal` (with `.reveal--fade` and `.reveal--on-load`) puts the animation and its `view()` timeline on one element, so it scrubs with the scroll and needs no wrapper. `.reveal-once` puts the timeline on a wrapper and runs `reveal-up` once on its element children, `> *` rather than a class on the card, so `articleCard` stays reusable on pages that do not reveal it. The child has to be something `transform` applies to: `_tags.css` gives the tag link `display: inline-block` for that reason, and on `/tags` the wrapper is the `<li class="tag__item">`, not the letter group. `.reveal-once` re-declares `--reveal-index`, `--reveal-index-cap`, `--reveal-delay`, `--reveal-duration` and `--reveal-distance` with card-shaped values, and `reveal-up` lands on the right end state for its child because `--reveal` is registered `inherits: false` with an initial value of `1`. `_articles.css` staggers its grid with `--reveal-index: mod(sibling-index() - 1, var(--items-per-row))`, and `--items-per-row` is already 1 below 960px. Both fall back to the revealed element: `.reveal` keeps its timeline inside `@supports (animation-timeline: view())` and has a `prefers-reduced-motion: reduce` escape, and `.reveal-once` declares its whole mechanism inside `@media (prefers-reduced-motion: no-preference)` and `@supports (animation-timeline: view())`, leaving nothing but tuning custom properties outside. Fusing the modifier drops `.reveal--fade` and `.reveal--on-load` to one class of specificity, so they only win by source order; keep them after `.reveal` in the file.
- **An `animation-timeline` goes inside `@supports (animation-timeline: …)`, and the animation and initial state it drives go with it unless the animation's last frame is the un-animated look.** Without the feature, `animation: x both` runs in zero seconds and holds its last frame: an unguarded `clip-out` clips a Project's image away, and `bold` makes every Table of Contents entry bold. `.reveal` leaves `reveal-up` outside because its last frame is the revealed element, which `@starting-style` then fades in on load. The block sits inside `@media (prefers-reduced-motion: no-preference)` too, because the reset in `reset.css` shortens durations and a scroll timeline ignores the duration the reset shortens: only keeping the declaration out of the query stops the animation for a reader who asked for less motion. The docs test rejects a new `animation-timeline` outside such a block. A layout that holds only while a timeline runs goes inside the same block, over a layout that reads on its own. `project-section.css` fixes each Project's image in place inside the block, because only `clip-out` uncovers the next one, and lays the image out beside its text in flow outside it, so a browser without scroll timelines and a reader who asked for less motion get a column of Projects each showing its own image. The docs test rejects `position: fixed` outside the block in a stylesheet that scrolls an animation.
- **View transitions stop for a reader who asked for less motion, in two places.** `base.css` opts every same-origin navigation into a cross-document view transition with `@view-transition { navigation: auto }`, and a later rule under `prefers-reduced-motion: reduce` sets `navigation: none`, which keeps the browser from capturing snapshots and running the transition at all. `navigation` is a descriptor of that rule, not a property, so it is never written on an element: `html, body` once carried it and it did nothing. The reset does not reach the `::view-transition-group(*)`, `::view-transition-old(*)` and `::view-transition-new(*)` pseudo-elements, so the same query removes their animation for the transitions the `ClientRouter` runs inside one document. Astro emits that rule itself only on a page that names an element for a transition, which `/tags`, `/privacy-policy` and `/terms-and-conditions` do not. The docs test holds both halves.
- **Rules one component uses live in its stylesheet, not in the global cascade.** `@keyframes` sit beside the stylesheet that reads them (`toc-slide-in` and `bold` in `table-of-contents.css`, `shrink` in `logo.css`, `clip-out` in `project-section.css`), because a stylesheet loads only where its component renders. `global/animations.css` keeps the ones a global stylesheet reads, the `reveal-*` set, and would keep one that two component stylesheets share. A global stylesheet selects no class a component owns, bar the `:not()` list in the default `svg` fill of `base.css`, and `reveal.css` names only the reveal blocks: a component that reveals its items opts in from its own stylesheet, as `article-slider.css` does for the slider's timeline. The docs test holds all three.
- **`sibling-index()` and `sibling-count()`** give a list item its position with no attribute, no loop variable and no `@supports not (z-index: attr(…))` fallback block, and they are better supported than a typed `attr()`. Three things about them are not obvious:
	- **The property has to be registered, or the value is wrong on every descendant.** A tree-counting function inside an *unregistered* custom property is not resolved where it is declared: it is substituted wherever the token stream finally lands, so a child reading `var(--index)` gets its *own* sibling index, which is 1 for an only child. Typed `attr()` does not behave this way, which is what makes the trap invisible when you swap one for the other. `--index`, `--stack-index` and `--reveal-index` are therefore `@property`-registered in `variables.css`, which forces resolution at computed-value time and makes the inherited value the declaring element's, and the docs test rejects an unregistered one. Registration also *is* the fallback: a browser without the function drops the declaration as invalid at computed-value time and the element takes the initial value, which is the flat layout.
	- **They count 1 in SVG.** Chromium answers 1 from both functions for every `<circle>`, `<rect>` or `<path>`, whatever its position. `themeToggle` is the one list here on `data-index` + typed `attr()` with an `nth-child` fallback, and that is why: its six dots are SVG children. `.reveal` reads `data-reveal-index` the same way because its stagger runs across parents (`welcome`'s headline and aside), which no sibling count reaches.
	- **They count *element siblings*, not matching ones.** So a list whose items are the only children of their parent reads `calc(sibling-index() - 1)` and nothing more, while `.project-list__item` sits after a `<header>` and carries the `- 2` that offset costs. Where an offset would be load-bearing, cancel it instead of writing it down: `.project-section` stacks on `calc(sibling-count() - sibling-index())`, whose two offsets cancel, so the z-index descends correctly however many non-section siblings the page puts around them.

## Mixed-in utilities

`global/modifiers.css` is the whole of `@layer modifiers`: cross-block behaviour that BEM treats as a *block used as a mix*, applied next to a component's own block class rather than copied into it. The table is the census: every block that stylesheet declares has a row here, and adding one without a row fails the docs test.

| Utility | What it does |
| --- | --- |
| `underline-on-hover` | Grows a `background-image` underline from 0% to 100% on hover; the fused `underline-on-hover--active` pins it open. |
| `clickable` | Pointer cursor and a press-scale on `:active`, skipping `canvas` and disabled controls. |
| `inverted-color-scheme` | Flips `color-scheme` against the page in both directions, for the sections censused under [Colour scheme](#colour-scheme), and is what the header watches to invert with them. |
| `current-page` | Paints the entry for the route you are already on in `--primary-main` (header links, the last breadcrumb). |
| `item-wrapper` | Gives a list item a positioning context, so a card's stretched `inset: 0` link (`.article-card__link`) covers the whole item instead of the nearest positioned ancestor. |
| `visually-hidden` | Takes an element out of the page's appearance while leaving it to a screen reader and the tab order; `display: none` would remove a control from both. |
