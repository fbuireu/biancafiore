# Coding standards

What a review checks a diff against. The words are the ones [GLOSSARY.md](./GLOSSARY.md) defines, the reasons are in [docs/adr/](./docs/adr/), and what an implementer needs while working is in the `AGENTS.md` guides.

**hard** marks a rule whose breach is a defect: report it with the rule. **judgement** marks a call the reviewer weighs against the diff: report it as a question. A rule here outranks the smell baseline; where it endorses something a smell would flag, the case is listed under *Deliberate overrides of the smell baseline* at the end.

Every rule carries an id, and a finding cites it with this file: `CODING_STANDARDS.md A3`. An id is never reused, so a retired rule leaves a gap in its section's numbering. A rule marked *check pending* is mechanical, and it leaves this body in the commit that lands its check. The process around a change (commit types, the pull request title a squash merge lands) is [CONTRIBUTING.md](./.github/CONTRIBUTING.md)'s.

## Tooling already enforces

No rule below restates these, and a diff that breaks one fails CI:

- Biome ([`biome.json`](./biome.json)): formatting, import order and lint, `noConsole` included, every object shape declared an `interface`, never a `type` alias of an object literal (`useConsistentTypeDefinitions`), and every element read from an array's end through `.at()` (`useAtIndex`).
- Strict `tsc` ([`tsconfig.json`](./tsconfig.json)) and `astro check`, which through `lib` reject a built-in the Workers runtime or a stable Safari lacks, `Temporal` among them.
- commitlint ([`commitlint.config.ts`](./commitlint.config.ts)): the commit format, on the commit and on the pull request title.
- The coverage floor ([`vitest.config.ts`](./vitest.config.ts)).
- `pnpm test:docs` ([`docs/docs-consistency.test.ts`](./docs/docs-consistency.test.ts)), which holds every document to the claims it can check, every Mermaid diagram in every Markdown file to `look: handDrawn` and `layout: dagre`, so a renderer that defaults to ELK cannot redraw it, the CI/CD wiki page to every workflow, composite action, secret and variable the workflows read and to `Verify`'s parallel steps, and the code to these:
  - no comment in hand-written source (`src`, `e2e`, `docs/*.test.ts`, the root configs and the stylesheets), doc comments included, bar the tool directives `biome-ignore`, `@ts-expect-error` and `/// <reference`;
  - one TypeScript argument passed positionally and two or more as one object, in production code, the tests, `e2e` and the docs test alike: no declared function or `const` arrow takes two positional parameters, no `…Params` type or inline parameter type declares a single field of its own (a wrapper around one value adds a type and a destructure for nothing and hides that the function takes a single subject), and a destructured parameter is typed `<FunctionName>Params`, a type two or more functions take that is named for their role rather than after one of them, or the record it unpacks, never an inline type or an `…Options` name;
  - an import that leaves its layer or feature written with the alias and one that stays inside it written relative, so an alias always marks a crossed boundary, and nothing outside `src/actions` importing from it;
  - every named export in `src` imported by another file, a test included, bar the routes, the middleware, the live config, the Worker entry, the action binding and `logging/logger.ts`, which the framework or the sibling repositories fix, so a name nothing reaches stays private;
  - every name `@shared/ui` exports read from two units at least (a layer or a feature), so what one feature reads stays with that feature;
  - the layer map: `live.config.ts` alone reaches `@application`, `500.astro`'s logger is the one import a page or the middleware makes into `@infrastructure`, drawn as the dotted exception, and the domain reaches no other layer;
  - domain and DTO purity: no Effect, I/O or env access, every DTO mapper synchronous, EmDash types stopping at `src/application`, and every schema named `<concept>Schema`, in the singular;
  - every package a hand-written module imports declared in `package.json`, so none resolves because another package happened to hoist it;
  - every `localeCompare` in `src` given a locale, the one `src/const/locale.ts` fixes, so no order a visitor sees depends on the machine that built it;
  - every date a module prints through `toLocaleDateString`, `toLocaleTimeString` or `toLocaleString` pinned to a `timeZone`, and a time named with its `timeZoneName`, so no line a reader sees depends on the zone of the machine that wrote it;
  - the read path under `src/ui`: content through `astro:content`'s live collections, `getLiveCollection` and `getLiveEntry` called by `core/utils/entries.ts` alone, no `@infrastructure`, `emdash` or `effect` import, and no `index.ts` barrel under `src/ui/modules`;
  - a content URL spelled in `@const` alone: no literal `/articles/`, `/tags/` or `/projects/` path and no `PAGES_ROUTES` entry joined to a slug anywhere else;
  - `astro:env/server` read lazily inside a layer, `Effect.die` in every layer that reads a secret, every tagged error declared in `src/infrastructure/errors.ts`, and `drizzle-orm` imported in `src/infrastructure/db` alone;
  - logging through `logger` or `LoggerService`, never `Effect.log*`; the plain `logger` imported by `500.astro` and the `LoggerService` layer alone; the `LoggerService` annotation on every program that logs; and the tag-to-status mapping in `contactErrorResponse`;
  - a bare `fetch` doubled with MSW rather than by replacing the global, no test writing the process environment, every `vi.stubGlobal`, `vi.stubEnv`, `vi.spyOn` and `vi.useFakeTimers` in a test file undone by `vi.unstubAllGlobals()`, `vi.unstubAllEnvs()`, `vi.restoreAllMocks()` or `vi.useRealTimers()` in an `afterEach` or `afterAll`, a document a dom test writes into emptied there too (`cleanup()`, `document.body.innerHTML = ""`) and never in a `beforeEach`, and no year read off the real clock and no `Date.now()` bracket in a unit test, since a bracket passes whatever the code computed between its two readings and a year read off the clock moves the expected value every January;
  - no cast on what a `.json()` or `JSON.parse` call answers, in production code, and Zod never declared a dependency and imported only through `@shared/utils/zod`, which reads `astro/zod` and turns its JIT off before any schema exists, because an object schema otherwise probes `new Function` as it is built, which a policy without `'unsafe-eval'` refuses and reports on every page that builds one;
  - BEM modifier syntax, component file names, bundled scripts initialised on `astro:page-load`, the hydration roots and their directives, and no `memo`, `useMemo` or `useCallback`, since `astro.config.ts` compiles every component with the React Compiler;
  - the cascade layers, the style censuses the styles guide keeps, every `animation-timeline`, and any `position: fixed` it uncovers, inside `@supports (animation-timeline: …)` and `@media (prefers-reduced-motion: no-preference)`, view transitions stopped under `prefers-reduced-motion: reduce`, a `@keyframes` beside the one stylesheet that reads it, no global rule for a class a component owns, the stretch arrow's morph, the box an arrow waits in and the slider's default ramp written once, no atomic utility its own element's block settles, a static `id` only where something reads it, no colour token registered with `@property`, every custom property that counts siblings registered, a count read by `sibling-count()` and never through `attr()`, and a colour literal in `variables.css` alone, with no hex colour in a module under `src/ui`;
  - every `coverage.exclude` glob matching a file, `--pass-with-no-tests` on `test:e2e:changed` alone, no shell substitution in a package script, and every deploy's `--message` the one token `<sha>-<event>` the deploying repositories share;
  - every `.releaserc.json` the release configuration the sibling repositories share, with no key or plugin beyond what the repository's shape adds and laid out as Biome lays it out, its release commit `chore(<scope>): release ${nextRelease.version} [skip ci]` scoped to the package it releases, and every plugin it names, and `semantic-release`, declared at one version in the `package.json` that runs it, beside no other release package, and the release commit let past commitlint by its `ignores`, whatever its notes say;
  - Playwright running the `chromium` and `webkit` projects alone, in CI and locally alike, and every workflow job that runs it installing both browsers behind a cache keyed on them;
  - every spec taking `test` and `expect` from `e2e/fixtures.ts`, which hands the preview's Cloudflare Access token to the preview's origin alone, and no Playwright config or spec setting `extraHTTPHeaders`;
  - no `BACKLOG.md` anywhere in the tree, and no `Known inconsistencies`, `Known defects` or `Known breaches` heading in any document;
  - this file: every rule between this list and the smell overrides opening with its id and its **hard** or **judgement** label, no id carried by two rules, and every id in a section drawn from one letter;
  - no object literal in a type alias but as a member of its union or beside the primitive it brands, nor one wrapped in `Readonly`, `Partial` or `Required`, so a shape built on others is an `interface` that `extends` them: `extends` reports a field the shapes disagree on where it is declared, where `&` folds it into `never` in silence, and the compiler caches an interface's relations by name and names it in an error, where it recomputes an intersection and spells it out;
  - one `security.txt` on every site the repository serves, counted under every `public` or `assets` folder, with `Contact`, `Expires`, `Preferred-Languages`, `Canonical` and `Policy` in that order, its `Canonical` the site's origin in `SITE_URL` plus `/.well-known/security.txt`, its `Policy` this repository's, and its `Expires` an ISO 8601 instant 30 days to two years from the day the suite runs, which reads the real clock on purpose so `main` turns red a month before the file lapses;
  - every `uses:` of another repository pinned to a full commit SHA with its version or branch in a trailing comment, and no comment in a YAML file (`pnpm-lock.yaml`, which pnpm writes, aside) but that one, a tool directive and the line Renovate writes above an entry it adds to `minimumReleaseAgeExclude`.

## Every change

- `G0` **hard**: A change carries everything the maintenance contract in [AGENTS.md](./AGENTS.md) and the guide of each folder it touches ask of it, in the same commit, and keeps every guardrail those guides state: the `logging/` files in step with the sibling repositories, `siteChrome` as the one reader of `HIDE_CHROME`, `Features.LightDark` in the lightningcss exclusions. A follow-up commit is a promise, not a fix.

## Across the tree

- `B1` **hard**: Name every folder, type, field, function and test after the term `GLOSSARY.md` defines, never a word it lists under _Avoid_, for that concept or for anything a reader could take for it, because a name that disagrees with the glossary is a defect in one of the two ([ADR 0012](./docs/adr/0012-pragmatic-ddd-domain-layer-anti-corruption-layer.md)). The _Avoid_ lists govern the names of concepts, not a vendor's own terms for its records (`entry`, an Astro `id`, `reference()`).
- `B2` **hard**: Keep Featured Article and Favorite apart (`isFeaturedArticle`, `isFavorite`), because the reader-facing lead of the Blog and the Author's own pick are chosen for different reasons.
- `B3` **hard**: Hold a class or object method to the one-positional, two-as-one-object rule the contract suite holds declared functions and `const` arrows to, because the suite does not read methods. A signature the runtime or a vendor owns (a route handler, a component's `Props`, a vendor's options object) stays that owner's type.
- `B4` **hard**: Name a parameter object the contract suite does not read (a class or object method's, one taken whole rather than destructured) after the function that takes it, `<FunctionName>Params`, so a reader landing on the type finds what takes it; a function handed one record (a domain object, a row, a vendor query or response, one event) keeps that record's type. Sibling functions that take the same input may share one type named for that role (`LogParams`, which `info`, `warn` and `error` take). A React component takes `<Component>Props` and an Astro component `Props`, the name Astro reads.
- `B5` **judgement**: Vary behaviour under test by mocking the module the code reads (`astro:env/client`) or stubbing a variable with `vi.stubEnv`, never by adding a parameter only a test passes, because that is an interface nothing else needs.
- `B6` **hard**: Implement a rule once and call it from every site that needs it, widening its input type to reach a new reader (`sortFavoriteFirst` over `Pick<ArticleSummaryDTO, "isFavorite" | "publishDateISO">`), because a second copy drifts with nothing to catch it: a tolerant one is how one entry sorted last in the Tag Index and read as the epoch on About ([ADR 0019](./docs/adr/0019-three-questions-before-modelling.md)).
- `B7` **judgement**: Give each decision one owning module and let callers take its answer (`createRelatedArticles`, `siteChrome`, `tagPageCopy`), because a branch restated at a call site drifts from its owner.
- `B8` **hard**: Declare a string that two places must agree on once, as an exported constant the template, the stylesheet and the script all read (`EMAIL_BUTTON_CLASS`, `THEME_STORAGE_KEY`, the Contact tab's query key), because two literals meant to be equal are invisible to Biome and `tsc` ([ADR 0005](./docs/adr/0005-theme-token-families-and-inline-bootstrap.md), [ADR 0013](./docs/adr/0013-analytics-gated-behind-cookie-consent.md)). A test asserts what is already out there (the `?tab=appointment` a shared link carries, the stored `dark` a returning visitor has) as a literal, because that literal is the oracle that catches a change breaking a public contract; a hook the test only locates an element or a value by (a class, a storage key) is read from its one declaration.
- `B9` **hard**: Read a value whose shape the types cannot prove (a JSON answer, a CMS field typed `any`, a query parameter, a `data-` attribute, a vendor global) as `unknown` and check it with a zod schema before reading any field of it, never with a cast, because a cast checks nothing at run time and a malformed value then fails far from its source: through a cast, an empty siteverify answer blames the visitor and an unpublished embed fails the page naming nothing. Name the schema `<concept>Schema` after what it checks, declare it beside its one reader (beside the module its readers share when they sit in one layer, as `resolvedImageSchema` sits in `dto/shared/images.ts`, which every DTO carrying an image calls, and in the domain when several layers read it, as `contactFormSchema` is), and infer the type from it; check with `.validate()` where the answer is a yes or no, and with `.safeParse()` where the caller reads the parsed value or the issue. `validateContact` reads both, and a schema that transforms or defaults needs `.safeParse()`, since `.validate()` narrows to the input type, its `z.input` rather than its `z.infer`. A browser module outside `/contact` and the globe compares literally instead (`readTheme`, `isColumnsEnabled`, `isGreenHost`), for the size reason the [modules guide](./src/ui/modules/AGENTS.md) gives.
- `B10` **judgement**: Before a concept gets a type, a wrapper or a schema of its own, ask in order whether the illegal state can be reached, whether anything reads it and whether it crosses a boundary; a no to all three means writing the rule down (an assertion, a guide line, an ADR) instead of encoding it ([ADR 0019](./docs/adr/0019-three-questions-before-modelling.md)).
- `B11` **judgement**: Send a failure through the typed error channel when a caller must answer it differently, and make it a defect when it is our bug or an unrecoverable misconfiguration (a template that cannot render, a secret a live layer cannot build without, which the `Effect.die` message names), because a typed error promises the caller a choice ([ADR 0004](./docs/adr/0004-effect-for-infrastructure-clients.md)).
- `B12` **judgement**: Fix a lint finding at its cause; a `biome-ignore` is for the irreplaceable case and says why, as the `gtag` `arguments` shim and the reduced-motion `!important` reset do.
- `B13` **hard**: Compose object shapes declared elsewhere as `interface X extends A, B`, never `type X = A & B`, which no check tells from an intersection with a union, because that takes the types. Keep `&` for a member an interface cannot extend (a union, a type parameter, a conditional type), and `type` for what an interface cannot say: a union, a mapped or conditional type, an alias of a primitive, a tuple or a function, and a computed type on its own (`z.infer`, `Pick`, `(typeof X)[keyof typeof X]`).
- `B14` **hard**: Give an interface a name no other interface in its scope carries, because two declarations of one name merge in silence; merging is for an augmentation of a global or a vendor's module made on purpose, in a declaration file or a `declare global` or `declare module` block (`Window`, and `@tgwf/co2`'s `CO2Options`, in `src/env.d.ts`).
- `B15` **hard**: Declare the return type of every function declared at a module's top level, exported or not, so a reader learns what it hands back without reading its body and a wrong return fails in the function rather than at its callers; a component that returns JSX, a nested function and a callback infer theirs. Type every parameter but a callback's, which takes its type from where it is passed.

## Domain (`src/domain`)

- `D1` **hard**: Print a date through `formatDate`, which pins `timeZone: "UTC"`, because the Worker renders in one time zone and locale and a contributor runs the tests in another ([ADR 0012](./docs/adr/0012-pragmatic-ddd-domain-layer-anti-corruption-layer.md)).
- `D2` **hard**: Return a changed value as a new one and leave the input untouched (`sortFavoriteFirst`, `buildTagIndexBuckets`, `resolveSlugCollisions`), because a DTO and a page can hold the same array.
- `D3` **judgement**: Name a rule after the editorial concept it encodes (`getReadingTime`, `deriveDescription`, `sortFavoriteFirst`), not after the mapper or the page that calls it.
- `D4` **hard**: Build the Table of Contents from the `ArticleHeading` list the renderer collected while writing the body, never by parsing rendered HTML, because an anchor id derived twice drifts from the one the body carries.

## Application (`src/application`)

- `A1` **hard**: Derive a DTO type from its schema (`z.infer`, or a lookup such as `ArticleDTO["tableOfContents"]`), and keep hand-written types for shapes no schema validates, because a second declaration of a validated shape drifts from the one Astro enforces.
- `A2` **hard**: Turn a raw entry into domain fields in exactly one function, owned by the concept it maps, and call it from every other mapper (`createAuthor` for the Byline, `articleSlug` and `articleReference` for every Article reference), because two hand-copied field lists are how a Byline and an Author Tag disagree.
- `A3` **hard**: Narrow a link-or-entry union on `"fields" in entry` or a schema, never by a cast: refuse an unresolved link the page cannot do without by its id (an Article no byline credits, an image Asset), and drop an unresolved member of a list (a Tag, a Related Article) or an embed in an Article's body, because a cast turns an unpublished target into a crash that names nothing and a withdrawn list member or embed is normal editorial state ([ADR 0019](./docs/adr/0019-three-questions-before-modelling.md)).
- `A4` **hard**: Refuse malformed CMS data where it is mapped, with a message that names the concept, what failed, the entry or the offending value, and what it would break ("…is credited to no byline, so no byline can name it"), because one entry failing every request that renders it, with a 500, is the chosen trade over one page rendering wrong ([ADR 0019](./docs/adr/0019-three-questions-before-modelling.md)).
- `A5` **hard**: Normalise at this boundary so the domain DTO is total: trim every string that identifies, keys or orders an entry (a Slug, a collection key, a name the Tag Index sorts), default optional fields with `??`, and keep an asset URL the path the CMS client resolved it to, which only `absoluteUrl` turns into a full URL where a page writes one out, because a `.trim()` or a URL rebuilt downstream means a mapping was skipped ([ADR 0012](./docs/adr/0012-pragmatic-ddd-domain-layer-anti-corruption-layer.md)).
- `A6` **hard**: Let the DTO choose which raw field feeds a rule and let `@domain/<concept>/rules` decide what a field's value means, because reading-time maths or description trimming inside a mapper hides an editorial rule from its tests; a decision over the whole batch that needs the raw links (Related Articles) may live in a named DTO helper ([ADR 0012](./docs/adr/0012-pragmatic-ddd-domain-layer-anti-corruption-layer.md)).
- `A7` **judgement**: Key a collection's `id` on what the glossary says identifies the concept (one Author is one Slug), and write down a key that is not unique, as `testimonials` keeps the Quotee's name ([ADR 0019](./docs/adr/0019-three-questions-before-modelling.md)).
- `A8` **judgement**: Store in a collection what identifies an entry, never how one page arranges it (the Tag Index's letter buckets are `buildTagIndexBuckets`, called from the page), because every other reader would have to undo a stored arrangement.
- `A9` **judgement**: Declare a query's `select` list beside the helper that reads those fields, so the list and its reader sit in one place.
- `A10` **judgement**: Treat a `limit` in a loader query as an editorial decision (this page wants five), because `fetchEntries` already pages until the collection is exhausted.
- `A11` **judgement**: Hand an I/O step every source at once and let the module doing the I/O bound its concurrency (`fetchEntries` reads every reference at once, at most `REFERENCE_READS_IN_FLIGHT` in flight), because a per-entry `await` sizes the burst by the collection.

## Infrastructure (`src/infrastructure`)

- `I1` **hard**: Give the `Database` and `EmailClient` tags the operations the site performs (`findLatestContactSince`, `insertContact`), each answering `Effect.Effect<A, XError>`, and keep the SDK or query builder inside the live layer, because a tag that hands back the vendor lets callers bypass its error type; a new query is a new method. `CmsClient` hands back EmDash's own entries because `src/application` is the anti-corruption layer, and `LoggerService` answers `void` because a log cannot fail ([ADR 0004](./docs/adr/0004-effect-for-infrastructure-clients.md)).
- `I2` **hard**: Wrap each vendor call a live layer or an Effect program makes in `Effect.tryPromise` and map its `catch` to a tagged error carrying the vendor's message (`cause instanceof Error ? cause.message : String(cause)`) and the `cause`, so a thrown vendor error never escapes untyped; a call whose failure is our bug (rendering the email template) goes through `Effect.promise`, which makes it a defect.
- `I3` **hard**: Annotate an exported Effect program's whole return type, `Effect.Effect<A, E, R>`, because an inferred `E` or `R` widens silently and the annotated `E` is what keeps `ContactError` a closed census.
- `I4` **judgement**: File a third-party refusal by whose it is: a verdict the visitor earned (a low reCAPTCHA score, an expired token) is a `ValidationError`, and a failure of our configuration or of the service (siteverify unreachable, an answer that is not a verdict, a rotated secret) is a `RecaptchaError`, because only the first is the visitor's to hear.
- `I5` **hard**: Write visitor-facing copy only for `ValidationError` and `DuplicateContactError`, where each is raised or in `@domain/contact/schema.ts`, whose field messages the form, `validateContact` and the reCAPTCHA refusal share, and write every other message for the Worker log, because `contactErrorResponse` forwards those two verbatim and collapses the rest.

## Actions (`src/actions`)

- `H1` **hard**: Answer an unauthenticated caller with one refusal sentence whatever check fired, and log which check fired, because distinct wording turns the Contact form into an oracle over the contacts table.
- `H2` **hard**: Provide `ContactLayer` per request, in `answerContact` and inside the fold that maps its failures, never at module scope and never around that fold, because contact writes are per request and the `ManagedRuntime` behind `fetchEntries` serves CMS reads only, and because a layer that cannot be built must reach `contactErrorResponse` like any other failure rather than hand the secret it names to the visitor ([ADR 0004](./docs/adr/0004-effect-for-infrastructure-clients.md)).

## UI modules (`src/ui/modules`)

- `U1` **judgement**: Reach for React only where interaction demands it, since a hydration directive at a call site is the moment to ask whether CSS or an Astro component would do ([ADR 0009](./docs/adr/0009-css-first-javascript-only-when-necessary.md)).
- `U2` **judgement**: Pass an island only what it reads, projected in a tested `utils/` module beside the type (`toCityPoints`), because every prop is serialised into the page's HTML; bind a function prop inside the island (`ContactFormProvider`).
- `U3` **judgement**: Move a derivation out of `.astro` frontmatter into the component's `utils/` (`buildArticleShareLinks`), because a template is the one place a test cannot reach.
- `U4` **judgement**: Parameterise a component used in several places by the class its caller hands it, with the placement's rules in the caller's stylesheet (the `ArticleSlider` placements), because a copy per placement drifts.
- `U5` **judgement**: Keep a bundled `<script>` to an import and a call of its initialiser in the component's `utils/`, so the logic is tested and Biome, which skips Astro `<script>` blocks, lints it.
- `U6` **hard**: Guard a bundled script's initialiser with a `data-` flag when it wires an element that survives the `ClientRouter` swap or a widget the vendor mounts (the Calendly widget), because it runs again on every `astro:page-load`; an initialiser whose elements the swap replaces needs no flag.
- `U7` **hard**: Keep state that only JavaScript reads in a `data-` attribute, never in a class that styles nothing ([ADR 0014](./docs/adr/0014-bem-class-naming.md)).

## Routes (`src/pages`)

- `R1` **hard**: Pass `BaseLayout` one `metadata: Partial<SeoMetadata>` from every `.astro` route, and build every JSON-LD document with a `build*Schema` from `@modules/core/utils/jsonLd` rendered through `<JsonLd>`, because those builders are what make every URL in it absolute.
- `R2` **judgement**: Keep a route's own CSS in `_<route>.css` beside it, imported by that route alone: its `page--<route>` background, its layout and the layout of the HTML the article renderer emits. A background two routes share (`page--tags` is both the Tag Index and a tag) lives once, in a `_page-<name>.css` both import, and no two stylesheets carry the same rule block.
- `R3` **hard**: Show a visitor only the copy the page writes for them; a 500 page that prints `error.message` leaks what the Worker log is for.

## Styles (component stylesheets and `src/ui/styles`)

- `S1` **hard**: Namespace a component stylesheet under one block named after the component, with BEM elements beneath it (`.article-card__byline`), a `<block>-wrapper` around it where the layout needs one, and a header's atoms under the parent's block, because component CSS is global and the class name is its only isolation ([ADR 0014](./docs/adr/0014-bem-class-naming.md)).
- `S2` **hard**: Express state and variants as a modifier on their block, never as a bare class under a descendant (`.card .active`); an element that mixes two blocks takes one modifier per block, as the Contact tabs toggle `tabs__tab--active` with `underline-on-hover--active` ([ADR 0014](./docs/adr/0014-bem-class-naming.md)).
- `S3` **judgement**: Reach for an existing mix (`underline-on-hover`, `clickable`, `inverted-color-scheme`, `current-page`, `item-wrapper`, `visually-hidden`) before writing a per-block copy; a new behavioural mix goes in `global/modifiers.css` and a typographic or layout one in `global/global.css`, chosen by the layer it has to beat ([ADR 0014](./docs/adr/0014-bem-class-naming.md)).
- `S4` **hard**: Hang state that restyles several unrelated blocks on the `page` block on `<html>` (`page--menu-open`) and consume it by descent, because `<html>` is the only ancestor every such block shares ([ADR 0014](./docs/adr/0014-bem-class-naming.md)).
- `S5` **hard**: Keep a rule only one component uses in that component's stylesheet, because `@styles/global` holds cross-cutting rules only.
- `S6` **judgement**: Build from tokens rather than magic numbers: `--font-size-*` from the ladder, the nearest `--space-*` step, vertical spacing from `--rhythm`, colour from a family step, so a new value is a step added to a family ([ADR 0005](./docs/adr/0005-theme-token-families-and-inline-bootstrap.md)).
- `S7` **hard**: Put a new colour token in the family that matches how it behaves, a `light-dark()` pair to follow the scheme or the `[data-theme]` set to invert on its own, because the wrong family looks right until a section inverts ([ADR 0005](./docs/adr/0005-theme-token-families-and-inline-bootstrap.md)).
- `S8` **judgement**: Scale type with its container through a `cqi` `clamp()` whose floor is the old fixed size, and query the page container (`@container home-page (…)`) rather than the viewport, because the page containers are what component CSS is laid out against.
- `S9` **judgement**: Use the `.editorial-*` utilities for editorial type and `.editorial-section-title` for any new section heading, because `.section-title` survives only for the components still on it.
- `S10` **judgement**: Reveal a leaf element with `.reveal` and a listing with `.reveal-once` on a wrapper whose element children animate, because the first scrubs with the scroll and the second fires once; only a grid sets `--reveal-index` ([ADR 0007](./docs/adr/0007-css-scroll-driven-reveal-animations.md)).
- `S11` **hard**: Index a list item in CSS with `sibling-index()` or `sibling-count()`, not a `data-index` the template counts out, except for SVG children, which count 1 (`themeToggle`).
- `S12` **hard**: Make an animation's un-animated state the one a visitor without the feature sees, with `prefers-reduced-motion` handled once in `reset.css` unless a component's un-animated state differs from its end state, because content must never stay hidden behind a missing feature ([ADR 0007](./docs/adr/0007-css-scroll-driven-reveal-animations.md)).
- `S13` **judgement**: Size an iframe that should follow its content with `frame-sizing: content-height` on top of `height: auto` and a `min-height` equal to the size it has today, because the embedded page decides when the property takes effect: until it opts in with `<meta name="responsive-embedded-sizing">`, an iframe left at `height: auto` falls back to 150px in a browser that implements the property.
- `S14` **judgement**: Use modern CSS against the Chromium-forward baseline (`light-dark()`, `color-mix`, `round()`, `@starting-style`) with no prefix stacks or polyfills, and add JavaScript only when CSS cannot express the effect ([ADR 0009](./docs/adr/0009-css-first-javascript-only-when-necessary.md)).
- `S15` **judgement**: Align an icon beside a label that can wrap with the label's first line, through `.icon-first-line` on the icon and a row aligned to the start, never with a hand-tuned margin, because a nudge holds for one font size and one icon size and a centred row moves the icon to the middle of a wrapped label.

## Tests

- `T1` **hard**: Assert in a live layer's own test the exact keys its tag hands out (`Object.keys(...).toSorted()`), so a re-exported vendor object fails a test.
- `T2` **judgement**: Give each DTO test file the two batch assertions the loaders rely on (an empty batch maps to an empty array, and the batch keeps its order), and build raw fixtures with a `make<Concept>` factory whose `Make<Concept>Params` default everything, so each case states only what it varies.
- `T3` **judgement**: Name a test after the behaviour and its reason ("…, because both bylines print the number unconditionally"), since the title is where a reader of a failing run looks for the why.
- `T4` **hard**: Double a dependency at the seam the architecture declares: a stub layer for anything behind an Effect tag and a `vi.mock` of a vendor module that leaves the process only in the live layer's own co-located test ([ADR 0017](./docs/adr/0017-doubles-at-the-seam-the-architecture-declares.md)).
- `T5` **hard**: Test a loader by swapping `CmsClient` for `cmsClientDouble`, whose `layer` is the stub, and keeping the real `fetchEntries`, because the runtime, the batching and the credential bail are what every loader relies on ([ADR 0016](./docs/adr/0016-vitest-resolves-astro-modules-itself.md)).
- `T6` **hard**: Undo in an `afterEach` (an `afterAll` for a change made once for the whole file) whatever else a test changes outside itself (a property assigned onto `window`, a controller whose signal a wiring listens on), because a line at the end of a test body never runs once an assertion above it fails and the change leaks into every later test in the file.
- `T7` **hard**: Pin the clock a case depends on (`vi.useFakeTimers({ toFake: ["Date"] })` and `vi.setSystemTime`) and assert the exact instant or year it yields.
- `T8` **judgement**: Build a double as a factory that returns what it recorded (`calls`, `inserted`, `sent`, `lines`), scoped to the test; `cmsLayer.ts` keeps module state and a reset because `vi.mock`'s factory reads it ([ADR 0017](./docs/adr/0017-doubles-at-the-seam-the-architecture-declares.md)).
- `T9` **judgement**: Assert the recorded `calls` whenever a double answers a wildcard host, because the wildcard answers a wrong request as readily as the right one ([ADR 0017](./docs/adr/0017-doubles-at-the-seam-the-architecture-declares.md)).
- `T10` **judgement**: Skip an end-to-end case that needs chrome `HIDE_CHROME` removes, with a reason naming what is missing, so the flag never turns a real failure into a pass ([ADR 0018](./docs/adr/0018-hide-chrome-replaces-the-page.md)).
- `T11` **hard**: Tag a case `@smoke` only for what proves the Worker answers on every deploy, never a result that depends on the caller's address, and keep the four cases every repository that deploys runs (a titled homepage, an unknown path answering 404, `robots.txt` served, `security.txt` served in date and byte for byte the file in `public/`) word for word, because a failing smoke run rolls production back. An image on `/articles` answering a WebP from `/_image` is this repository's fifth, because a refused transform breaks every image while every page still renders; it asks `/articles`, which every stage renders whatever `HIDE_CHROME` hides, past the cache, so it tests the version just deployed, and fetches the image from the page, because the zone answers 403 to an automated client on a datacenter address. What the served files say beyond that is the docs test's to assert.
- `T12` **hard**: Prove a new docs-test assertion by breaking the code it guards and watching it fail, permuting a pair rather than only renaming a token, because an assertion that never failed advertises coverage it lacks ([ADR 0015](./docs/adr/0015-docs-consistency-enforced-by-a-test.md)).
- `T13` **hard**: Guard every list a docs-test assertion derives from the repository (files, rows, matches) with a non-empty assertion or a synthetic self-test, because an assertion over an empty census passes whatever the tree holds ([ADR 0015](./docs/adr/0015-docs-consistency-enforced-by-a-test.md)).
- `T14` **hard**: Record a deliberate omission in the allowlist at the top of `docs/docs-consistency.test.ts`, and delete an allowlist that empties, because deleting the assertion is how that file stops being true ([ADR 0015](./docs/adr/0015-docs-consistency-enforced-by-a-test.md)).

## Workflows

- `C1` **hard**: Move a `uses:` pin's SHA and the version or branch in its trailing comment together, because the SHA is what runs, the comment is the only thing that makes it legible, and Renovate maintains both halves.
- `C2` **hard**: Put the reason for a line of YAML in the commit message, the pull request, an ADR or a rule here, and a gotcha an implementer would otherwise trip on in the *Gotchas* of [AGENTS.md](./AGENTS.md).

## Docs

- `G1` **hard**: Keep `GLOSSARY.md` to vocabulary: the term, one or two sentences on what it is, and the words it displaces, never how it is built, because mechanism belongs to the folder guide or an ADR.
- `G2` **hard**: State a rule once: a rule about how code is written here, a coupling or a gotcha in the guide of the folder it bites, a decision in an ADR; a wiki page says where the rule lives, because `docs/wiki/` is published and nothing checks a copy.
- `G3` **hard**: Write a guide in the present tense, holding what an implementer needs while working; the reason for a line goes in the commit message, the pull request, an ADR or a rule here, and history ("used to", "was", "until …") stays in git, because a guide is loaded into every session that works in its folder.
- `G4` **judgement**: Propose an ADR only for a decision that is hard to reverse, surprising without context and the result of a real trade-off, and link it from where it bites.
- `G5` **hard**: Delete a gotcha or an allowlist entry in the change that resolves it, because a stale entry is a false claim about the tree.
- `G6` **hard**: Fix a breach in the change that finds it, or report it on the pull request with the rule it breaks; no guide keeps a list of known inconsistencies, because an entry is a claim about the code that nothing keeps true.

## Deliberate overrides of the smell baseline

- **Primitive Obsession**: a Slug and an ISO publish date stay plain strings. Each is minted at one boundary (`articleSlug`, `publishDateISO`) and `@const/routes.ts` alone turns a Slug into a path, so a brand would touch every schema and `reference()` for a guarantee the boundary already gives ([ADR 0019](./docs/adr/0019-three-questions-before-modelling.md)).
- **Data Clumps**: two functions whose parameters merely coincide each keep their own `<FunctionName>Params`, because the type is named after what takes it, and siblings that take the same input may share one named for that role, as `info`, `warn` and `error` share `LogParams` in `logging/logger.ts`.
- **Duplicated Code**: `logging/logger.ts` is byte for byte what the sibling repositories carry and `logging/contract.ts` differs from theirs only in `LOG_SERVICE`, so a change to either is made in all three ([ADR 0020](./docs/adr/0020-logs-and-traces-leave-through-cloudflares-export.md)).
- **Duplicated Code**: the stated-version helpers (`VERSIONED_DEPENDENCIES` through `declaredIn`) in `docs/docs-consistency.test.ts` are byte for byte the same in biancafiore, contribKit and github-star-tracker, so a change to one is made in all three.
- **Duplicated Code**: the release-configuration rule (`BREAKING_PARSER_OPTS` through the `describe` that holds every release configuration to the shared one) in `docs/docs-consistency.test.ts` is byte for byte the same in biancafiore, contribKit, forever-pto and github-star-tracker, so a change to it is made in all four; only the shapes declared above it, which name each repository's files, differ.
- **Duplicated Code**: the id rule (the `describe` that gives every rule of this file an id a finding can cite) in `docs/docs-consistency.test.ts` is the same in biancafiore, contribKit, forever-pto and github-star-tracker, so a change to it is made in all four; only the floor its census holds and the call that reads this file differ.
- **Duplicated Code**: the shape rule (the `describe` that keeps every object shape an interface) in `docs/docs-consistency.test.ts` is the same in biancafiore, contribKit, forever-pto and github-star-tracker, so a change to it is made in all four; only the floor its census holds and the files it reads differ.
- **Duplicated Code**: the four smoke cases are word for word the same in every repository that deploys, so a difference between them is drift, not a variant.
- **Duplicated Code**: the Contact payload is validated at `defineAction`'s `input` and again in `validateContact`, because only the edge rejects an empty reCAPTCHA token and only the program is unit-testable; the `ManagedRuntime` behind `fetchEntries` and the per-request `ContactLayer` stay two runtimes ([ADR 0004](./docs/adr/0004-effect-for-infrastructure-clients.md)).
- **Middle Man**: `LoggerService` is a `Layer.sync` over the `logger` object, kept for the `R` signal that makes an unintended log a compile error ([ADR 0020](./docs/adr/0020-logs-and-traces-leave-through-cloudflares-export.md)).
- **Speculative Generality**: Effect tags and layers wrap the CMS, database and email clients although each has one consumer (`fetchEntries` for the CMS, the contact flow for the database and email), a heavy choice the ADR accepts ([ADR 0004](./docs/adr/0004-effect-for-infrastructure-clients.md)).
- **Shotgun Surgery**: a new content type edits its domain concept, its DTO, its loader, `src/live.config.ts` and `GLOSSARY.md` together by design ([ADR 0012](./docs/adr/0012-pragmatic-ddd-domain-layer-anti-corruption-layer.md)); a new inverting or container-scaled component also edits its census line in the styles guide.
- **Mysterious Name**: `ASTRO_DB_REMOTE_URL` and `ASTRO_DB_APP_TOKEN` keep the Astro DB name, because renaming means re-provisioning the secrets ([ADR 0003](./docs/adr/0003-drizzle-libsql-turso-over-astro-db.md)); `HIDE_CHROME` keeps a name that understates it until the flag is deleted ([ADR 0018](./docs/adr/0018-hide-chrome-replaces-the-page.md)).
