# Coding standards

What a review checks a diff against. The words are the ones [CONTEXT.md](./CONTEXT.md) defines, the reasons are in [docs/adr/](./docs/adr/), and what an implementer needs while working is in the `AGENTS.md` guides.

**hard** marks a rule whose breach is a defect: report it with the rule. **judgement** marks a call the reviewer weighs against the diff: report it as a question. A rule here outranks the smell baseline; where it endorses something a smell would flag, the case is listed under *Deliberate overrides of the smell baseline* at the end.

## Tooling already enforces

No rule below restates these, and a diff that breaks one fails CI:

- Biome ([`biome.json`](./biome.json)): formatting, import order and lint, `noConsole` included.
- Strict `tsc` ([`tsconfig.json`](./tsconfig.json)) and `astro check`.
- commitlint ([`commitlint.config.ts`](./commitlint.config.ts)): the commit format, on the commit and on the pull request title.
- The coverage floor ([`vitest.config.ts`](./vitest.config.ts)).
- `pnpm test:docs` ([`docs/docs-consistency.test.ts`](./docs/docs-consistency.test.ts)), which holds every document to the claims it can check, every Mermaid diagram to the `layout: dagre` it was drawn with, so a renderer that defaults to ELK cannot redraw it, and the code to these:
  - no comment in hand-written source (`src`, `e2e`, `docs/*.test.ts`, the root configs and the stylesheets), doc comments included, bar the tool directives `biome-ignore`, `@ts-expect-error` and `/// <reference`;
  - one TypeScript argument passed positionally and two or more as one object, in production code, the tests, `e2e` and the docs test alike: no function takes two positional parameters, no `…Params` type or inline parameter type declares a single field of its own, and a destructured parameter is typed `<FunctionName>Params`, a type two or more functions take that is named for their role rather than after one of them, or the record it unpacks, never an inline type or an `…Options` name;
  - an import that leaves its layer or feature written with the alias and one that stays inside it written relative, so an alias always marks a crossed boundary, and nothing outside `src/actions` importing from it;
  - every named export in `src` imported by another file, a test included, bar the routes, the middleware, the content config, the action binding and `logging/logger.ts`, which the framework or the sibling repositories fix, so a name nothing reaches stays private;
  - every name `@shared/ui` exports read from two units at least (a layer or a feature), so what one feature reads stays with that feature;
  - the layer map: `content.config.ts` alone reaches `@application`, and the domain reaches no other layer;
  - domain and DTO purity: no Effect, I/O or env access, every DTO mapper synchronous, Contentful types stopping at `src/application`, no local-time `Date` API in either layer, no in-place `.sort(`, `.reverse(` or `.splice(` in a domain rule, and every schema named `<concept>Schema`, in the singular;
  - every package a hand-written module imports declared in `package.json`, so none resolves because another package happened to hoist it;
  - every `localeCompare` in `src` given a locale, the one `src/const/locale.ts` fixes, so no order a visitor sees depends on the machine that built it;
  - every date a module prints through `toLocaleDateString`, `toLocaleTimeString` or `toLocaleString` pinned to a `timeZone`, and a time named with its `timeZoneName`, so no line a reader sees depends on the zone of the machine that wrote it;
  - the read path under `src/ui`: content through `astro:content`, `getEntry` called by `resolveArticle` and `resolveArticles` alone, no `@infrastructure`, `contentful` or `effect` import, and no `index.ts` barrel under `src/ui/modules`;
  - a content URL spelled in `@const` alone: no literal `/articles/`, `/tags/` or `/projects/` path and no `PAGES_ROUTES` entry joined to a slug anywhere else;
  - `astro:env/server` read lazily inside a layer, `Effect.die` in every layer that reads a secret, every tagged error declared in `src/infrastructure/errors.ts`, and `drizzle-orm` imported in `src/infrastructure/db` alone;
  - logging through `logger` or `LoggerService`, never `Effect.log*`; the plain `logger` imported by `500.astro`, `getImagePlaceholders` and the `LoggerService` layer alone; the `LoggerService` annotation on every program that logs; and the tag-to-status mapping in `contactErrorResponse`;
  - a bare `fetch` doubled with MSW rather than by replacing the global, no test writing the process environment, every `vi.stubGlobal`, `vi.stubEnv`, `vi.spyOn` and `vi.useFakeTimers` in a test file undone by `vi.unstubAllGlobals()`, `vi.unstubAllEnvs()`, `vi.restoreAllMocks()` or `vi.useRealTimers()` in an `afterEach` or `afterAll`, a document a dom test writes into emptied there too (`cleanup()`, `document.body.innerHTML = ""`) and never in a `beforeEach`, and no year read off the real clock and no `Date.now()` bracket in a unit test;
  - no cast on what a `.json()` or `JSON.parse` call answers, in production code, and Zod imported only from `astro/zod` and never declared a dependency;
  - BEM modifier syntax, component file names, bundled scripts initialised on `astro:page-load`, the hydration roots and their directives, and no `memo`, `useMemo` or `useCallback`, since `astro.config.ts` compiles every component with the React Compiler;
  - the cascade layers, the style censuses the styles guide keeps, every `animation-timeline`, and any `position: fixed` it uncovers, inside `@supports (animation-timeline: …)` and `@media (prefers-reduced-motion: no-preference)`, view transitions stopped under `prefers-reduced-motion: reduce`, a `@keyframes` beside the one stylesheet that reads it, no global rule for a class a component owns, the stretch arrow's morph and the slider's default ramp written once, no atomic utility its own element's block settles, a static `id` only where something reads it, no colour token registered with `@property`, every custom property that counts siblings registered, a count read by `sibling-count()` and never through `attr()`, and a colour literal in `variables.css` alone, with no hex colour in a module under `src/ui`;
  - every `coverage.exclude` glob matching a file, `--pass-with-no-tests` on `test:e2e:changed` alone, no shell substitution in a package script, and a `--message` on every deploy;
  - every `uses:` of another repository pinned to a full commit SHA with its version or branch in a trailing comment, and no comment in a YAML file (`pnpm-lock.yaml`, which pnpm writes, aside) but that one, a tool directive and the line Renovate writes above an entry it adds to `minimumReleaseAgeExclude`.

## Every change

- **hard**: A change carries everything the maintenance contract in [AGENTS.md](./AGENTS.md) and the guide of each folder it touches ask of it, in the same commit, and keeps every guardrail those guides state: the `logging/` files in step with the sibling repositories, `siteChrome` as the one reader of `HIDE_CHROME`, `Features.LightDark` in the lightningcss exclusions. A follow-up commit is a promise, not a fix.

## Across the tree

- **hard**: Name every folder, type, field, function and test after the term `CONTEXT.md` defines, never a word it lists under _Avoid_, for that concept or for anything a reader could take for it, because a name that disagrees with the glossary is a defect in one of the two ([ADR 0012](./docs/adr/0012-pragmatic-ddd-domain-layer-anti-corruption-layer.md)). The _Avoid_ lists govern the names of concepts, not a vendor's own terms for its records (`entry`, an Astro `id`, `reference()`).
- **hard**: Keep Featured Article and Favorite apart (`isFeaturedArticle`, `isFavorite`), because the reader-facing lead of the Blog and the Author's own pick are chosen for different reasons.
- **hard**: Pass one argument positionally and two or more as one object, so no `…Params` type and no inline parameter type declares a single field of its own, because a wrapper around one value adds a type and a destructure for nothing and hides that the function takes a single subject. A signature the runtime or a vendor owns (a route handler, a component's `Props`, a vendor's options object) stays that owner's type; it is never a local `…Params` with one field.
- **hard**: Name a parameter object after the function that takes it, `<FunctionName>Params`, so a reader landing on the type finds what takes it; a function handed one record (a domain object, a row, a vendor query or response, one event) keeps that record's type. Sibling functions that take the same input may share one type named for that role (`LogParams`, which `info`, `warn` and `error` take). The rule holds where the tooling cannot see it too (an object method, a parameter taken whole), and a React component takes `<Component>Props` and an Astro component `Props`, the name Astro reads.
- **judgement**: Vary behaviour under test by mocking the module the code reads (`astro:env/client`) or stubbing a variable with `vi.stubEnv`, restored by `vi.unstubAllEnvs()`, never by adding a parameter only a test passes, because that is an interface nothing else needs.
- **hard**: Implement a rule once and call it from every site that needs it, widening its input type to reach a new reader (`sortFavoriteFirst` over `Pick<ArticleDTO, "isFavorite" | "publishDateISO">`), because a second copy drifts with nothing to catch it: a tolerant one is how one entry sorted last in the Tag Index and read as the epoch on About ([ADR 0019](./docs/adr/0019-three-questions-before-modelling.md)).
- **judgement**: Give each decision one owning module and let callers take its answer (`createRelatedArticles`, `siteChrome`, `tagPageCopy`), because a branch restated at a call site drifts from its owner.
- **hard**: Declare a string that two places must agree on once, as an exported constant the template, the stylesheet and the script all read (`EMAIL_BUTTON_CLASS`, `THEME_STORAGE_KEY`, the Contact tab's query key), because two literals meant to be equal are invisible to Biome and `tsc` ([ADR 0005](./docs/adr/0005-theme-token-families-and-inline-bootstrap.md), [ADR 0013](./docs/adr/0013-analytics-gated-behind-cookie-consent.md)). A test asserts what is already out there (the `?tab=appointment` a shared link carries, the stored `dark` a returning visitor has) as a literal, because that literal is the oracle that catches a change breaking a public contract; a hook the test only locates an element or a value by (a class, a storage key) is read from its one declaration.
- **hard**: Read a value whose shape the types cannot prove (a JSON answer, a CMS field typed `any`, a query parameter, a `data-` attribute, a vendor global) as `unknown` and check it with a zod schema from `astro/zod` before reading any field of it, never with a cast, because a cast checks nothing at run time and a malformed value then fails far from its source: through a cast, an empty siteverify answer blames the visitor and an unpublished embed fails the build naming nothing. Name the schema `<concept>Schema` after what it checks, declare it beside its one reader (beside the module its readers share when they sit in one layer, as `assetFileSchema` is, and in the domain when several layers read it, as `contactFormSchema` is), and infer the type from it; check with `.validate()` where the answer is a yes or no, and with `.safeParse()` where the caller reads the parsed value or the issue. `validateContact` reads both, and a schema that transforms or defaults needs `.safeParse()`, since `.validate()` narrows to the input type, its `z.input` rather than its `z.infer`. A browser module outside `/contact` and the globe compares literally instead (`readPreference`, `isColumnsEnabled`, `isGreenHost`), for the size reason the [modules guide](./src/ui/modules/AGENTS.md) gives.
- **judgement**: Before a concept gets a type, a wrapper or a schema of its own, ask in order whether the illegal state can be reached, whether anything reads it and whether it crosses a boundary; a no to all three means writing the rule down (an assertion, a guide line, an ADR) instead of encoding it ([ADR 0019](./docs/adr/0019-three-questions-before-modelling.md)).
- **judgement**: Send a failure through the typed error channel when a caller must answer it differently, and make it a defect when it is our bug or an unrecoverable misconfiguration (a template that cannot render, a secret a live layer cannot build without, which the `Effect.die` message names), because a typed error promises the caller a choice ([ADR 0004](./docs/adr/0004-effect-for-infrastructure-clients.md)).
- **judgement**: Fix a lint finding at its cause; a `biome-ignore` is for the irreplaceable case and says why, as the `gtag` `arguments` shim and the reduced-motion `!important` reset do.

## Domain (`src/domain`)

- **hard**: Keep a rule deterministic on any machine: compare text with `localeCompare` given `DEFAULT_LOCALE_STRING`, and print a date through `formatDate`, which pins `timeZone: "UTC"`, because CI prerenders in one time zone and locale and an author builds in another ([ADR 0012](./docs/adr/0012-pragmatic-ddd-domain-layer-anti-corruption-layer.md)).
- **hard**: Return a changed value as a new one and leave the input untouched (`sortFavoriteFirst`, `buildTagIndexBuckets`, `resolveSlugCollisions`), because a DTO and a page can hold the same array.
- **judgement**: Name a rule after the editorial concept it encodes (`getReadingTime`, `deriveDescription`, `sortFavoriteFirst`), not after the mapper or the page that calls it.
- **hard**: Build the Table of Contents from the `ArticleHeading` list the renderer collected while writing the body, never by parsing rendered HTML, because an anchor id derived twice drifts from the one the body carries.

## Application (`src/application`)

- **hard**: Derive a DTO type from its schema (`z.infer`, or a lookup such as `ArticleDTO["tableOfContents"]`), and keep hand-written types for shapes no schema validates, because a second declaration of a validated shape drifts from the one Astro enforces.
- **hard**: Turn a raw entry into domain fields in exactly one function, owned by the concept it maps, and call it from every other mapper (`createAuthor` for the Byline, `articleSlug` and `articleReference` for every Article reference), because two hand-copied field lists are how a Byline and an Author Tag disagree.
- **hard**: Narrow a link-or-entry union on `"fields" in entry` or a schema, never by a cast: refuse an unresolved link the page cannot do without by its `sys.id` (a Byline's Author, an image Asset), and drop an unresolved member of a list (a Tag, a Related Article) or an embed in an Article's body, because a cast turns an unpublished target into a crash that names nothing and a withdrawn list member or embed is normal editorial state ([ADR 0019](./docs/adr/0019-three-questions-before-modelling.md)).
- **hard**: Refuse malformed CMS data where it is mapped, with a message that names the concept, what failed, the entry or the offending value, and what it would break ("…unresolved (`sys.id`), so no byline can name it"), because one entry failing the build is the chosen trade over one page rendering wrong ([ADR 0019](./docs/adr/0019-three-questions-before-modelling.md)).
- **hard**: Normalise at this boundary so the domain DTO is total: trim every string that identifies, keys or orders an entry (a Slug, a collection key, a name the Tag Index sorts), absolutise asset URLs in `createImage`, default optional fields with `??`, because a `.trim()` or a scheme added downstream means a mapping was skipped ([ADR 0012](./docs/adr/0012-pragmatic-ddd-domain-layer-anti-corruption-layer.md)).
- **hard**: Let the DTO choose which raw field feeds a rule and let `@domain/<concept>/rules` decide what a field's value means, because reading-time maths or description trimming inside a mapper hides an editorial rule from its tests; a decision over the whole batch that needs the raw links (Related Articles) may live in a named DTO helper ([ADR 0012](./docs/adr/0012-pragmatic-ddd-domain-layer-anti-corruption-layer.md)).
- **judgement**: Key a collection's `id` on what the glossary says identifies the concept (one Author is one Slug), and write down a key that is not unique, as `testimonials` keeps the Quotee's name ([ADR 0019](./docs/adr/0019-three-questions-before-modelling.md)).
- **judgement**: Store in a collection what identifies an entry, never how one page arranges it (the Tag Index's letter buckets are `buildTagIndexBuckets`, called from the page), because every other reader would have to undo a stored arrangement.
- **judgement**: Declare a query's `select` list beside the helper that reads those fields, so the list and its reader sit in one place.
- **judgement**: Treat a `limit` in a loader query as an editorial decision (this page wants five), because `fetchEntries` already pages until the collection is exhausted.
- **judgement**: Hand an I/O step every source at once and let the module doing the I/O bound its concurrency (`getImagePlaceholders` answers a `Map`), because a per-entry `await` sizes the burst by the collection.

## Infrastructure (`src/infrastructure`)

- **hard**: Give the `Database` and `EmailClient` tags the operations the site performs (`findLatestContactSince`, `insertContact`), each answering `Effect.Effect<A, XError>`, and keep the SDK or query builder inside the live layer, because a tag that hands back the vendor lets callers bypass its error type; a new query is a new method. `CmsClient` hands back Contentful's own collection because `src/application` is the anti-corruption layer, and `LoggerService` answers `void` because a log cannot fail ([ADR 0004](./docs/adr/0004-effect-for-infrastructure-clients.md)).
- **hard**: Wrap each vendor call a live layer or an Effect program makes in `Effect.tryPromise` and map its `catch` to a tagged error from `src/infrastructure/errors.ts` carrying the vendor's message (`cause instanceof Error ? cause.message : String(cause)`) and the `cause`, so a thrown vendor error never escapes untyped; a call whose failure is our bug (rendering the email template) goes through `Effect.promise`, which makes it a defect.
- **hard**: Annotate an exported Effect program's whole return type, `Effect.Effect<A, E, R>`, because an inferred `E` or `R` widens silently and the annotated `E` is what keeps `ContactError` a closed census.
- **judgement**: File a third-party refusal by whose it is: a verdict the visitor earned (a low reCAPTCHA score, an expired token) is a `ValidationError`, and a failure of our configuration or of the service (siteverify unreachable, an answer that is not a verdict, a rotated secret) is a `RecaptchaError`, because only the first is the visitor's to hear.
- **hard**: Write visitor-facing copy only for `ValidationError` and `DuplicateContactError`, where each is raised or in `@domain/contact/schema.ts`, whose field messages the form, `validateContact` and the reCAPTCHA refusal share, and write every other message for the Worker log, because `contactErrorResponse` forwards those two verbatim and collapses the rest.

## Actions (`src/actions`)

- **hard**: Answer an unauthenticated caller with one refusal sentence whatever check fired, and log which check fired, because distinct wording turns the Contact form into an oracle over the contacts table.
- **hard**: Provide `ContactLayer` per request inside the handler, never at module scope, because contact writes are per request and the `ManagedRuntime` behind `fetchEntries` serves CMS reads only ([ADR 0004](./docs/adr/0004-effect-for-infrastructure-clients.md)).

## UI modules (`src/ui/modules`)

- **judgement**: Reach for React only where interaction demands it, since a hydration directive at a call site is the moment to ask whether CSS or an Astro component would do ([ADR 0009](./docs/adr/0009-css-first-javascript-only-when-necessary.md)).
- **judgement**: Pass an island only what it reads, projected in a tested `utils/` module beside the type (`toCityPoints`), because every prop is serialised into the page's HTML; bind a function prop inside the island (`ContactFormProvider`).
- **judgement**: Move a derivation out of `.astro` frontmatter into the component's `utils/` (`buildArticleShareLinks`), because a template is the one place a test cannot reach.
- **judgement**: Parameterise a component used in several places by the class its caller hands it, with the placement's rules in the caller's stylesheet (the `ArticleSlider` placements), because a copy per placement drifts.
- **judgement**: Keep a bundled `<script>` to an import and a call of its initialiser in the component's `utils/`, so the logic is tested and Biome, which skips Astro `<script>` blocks, lints it.
- **hard**: Guard a bundled script's initialiser with a `data-` flag when it wires an element that survives the `ClientRouter` swap or a widget the vendor mounts (the Calendly widget), because it runs again on every `astro:page-load`; an initialiser whose elements the swap replaces needs no flag.
- **hard**: Keep state that only JavaScript reads in a `data-` attribute, never in a class that styles nothing ([ADR 0014](./docs/adr/0014-bem-class-naming.md)).

## Routes (`src/pages`)

- **hard**: Pass `BaseLayout` one `metadata: Partial<SeoMetadata>` from every `.astro` route, and build every JSON-LD document with a `build*Schema` from `@modules/core/utils/jsonLd` rendered through `<JsonLd>`, because those builders are what make every URL in it absolute.
- **judgement**: Keep a route's own CSS in `_<route>.css` beside it, imported by that route alone: its `page--<route>` background, its layout and the layout of the HTML the article renderer emits. A background two routes share (`page--tags` is both the Tag Index and a tag) lives once, in a `_page-<name>.css` both import, and no two stylesheets carry the same rule block.
- **hard**: Show a visitor only the copy the page writes for them; a 500 page that prints `error.message` leaks what the Worker log is for.

## Styles (component stylesheets and `src/ui/styles`)

- **hard**: Namespace a component stylesheet under one block named after the component, with BEM elements beneath it (`.article-card__byline`), a `<block>-wrapper` around it where the layout needs one, and a header's atoms under the parent's block, because component CSS is global and the class name is its only isolation ([ADR 0014](./docs/adr/0014-bem-class-naming.md)).
- **hard**: Express state and variants as a modifier on their block, never as a bare class under a descendant (`.card .active`); an element that mixes two blocks takes one modifier per block, as the Contact tabs toggle `tabs__tab--active` with `underline-on-hover--active` ([ADR 0014](./docs/adr/0014-bem-class-naming.md)).
- **judgement**: Reach for an existing mix (`underline-on-hover`, `clickable`, `inverted-color-scheme`, `current-page`, `item-wrapper`, `visually-hidden`) before writing a per-block copy; a new behavioural mix goes in `global/modifiers.css` and a typographic or layout one in `global/global.css`, chosen by the layer it has to beat ([ADR 0014](./docs/adr/0014-bem-class-naming.md)).
- **hard**: Hang state that restyles several unrelated blocks on the `page` block on `<html>` (`page--menu-open`) and consume it by descent, because `<html>` is the only ancestor every such block shares ([ADR 0014](./docs/adr/0014-bem-class-naming.md)).
- **hard**: Keep a rule only one component uses in that component's stylesheet, because `@styles/global` holds cross-cutting rules only.
- **judgement**: Build from tokens rather than magic numbers: `--font-size-*` from the ladder, the nearest `--space-*` step, vertical spacing from `--rhythm`, colour from a family step, so a new value is a step added to a family ([ADR 0005](./docs/adr/0005-theme-token-families-and-inline-bootstrap.md)).
- **hard**: Put a new colour token in the family that matches how it behaves, a `light-dark()` pair to follow the scheme or the `[data-theme]` set to invert on its own, because the wrong family looks right until a section inverts ([ADR 0005](./docs/adr/0005-theme-token-families-and-inline-bootstrap.md)).
- **judgement**: Scale type with its container through a `cqi` `clamp()` whose floor is the old fixed size, and query the page container (`@container home-page (…)`) rather than the viewport, because the page containers are what component CSS is laid out against.
- **judgement**: Use the `.editorial-*` utilities for editorial type and `.editorial-section-title` for any new section heading, because `.section-title` survives only for the components still on it.
- **judgement**: Reveal a leaf element with `.reveal` and a listing with `.reveal-once` on a wrapper whose element children animate, because the first scrubs with the scroll and the second fires once; only a grid sets `--reveal-index` ([ADR 0007](./docs/adr/0007-css-scroll-driven-reveal-animations.md)).
- **hard**: Index a list item in CSS with `sibling-index()` or `sibling-count()`, not a `data-index` the template counts out, except for SVG children, which count 1 (`themeToggle`).
- **hard**: Make an animation's un-animated state the one a visitor without the feature sees, with `prefers-reduced-motion` handled once in `reset.css` unless a component's un-animated state differs from its end state, because content must never stay hidden behind a missing feature ([ADR 0007](./docs/adr/0007-css-scroll-driven-reveal-animations.md)).
- **judgement**: Size an iframe that should follow its content with `frame-sizing: content-height` on top of `height: auto` and a `min-height` equal to the size it has today, because the embedded page decides when the property takes effect: until it opts in with `<meta name="responsive-embedded-sizing">`, an iframe left at `height: auto` falls back to 150px in a browser that implements the property.
- **judgement**: Use modern CSS against the Chromium-forward baseline (`light-dark()`, `color-mix`, `round()`, `@starting-style`) with no prefix stacks or polyfills, and add JavaScript only when CSS cannot express the effect ([ADR 0009](./docs/adr/0009-css-first-javascript-only-when-necessary.md)).

## Tests

- **hard**: Assert in a live layer's own test the exact keys its tag hands out (`Object.keys(...).toSorted()`), so a re-exported vendor object fails a test.
- **judgement**: Give each DTO test file the two batch assertions the loaders rely on (an empty batch maps to an empty array, and the batch keeps its order), and build raw fixtures with a `make<Concept>` factory whose `Make<Concept>Params` default everything, so each case states only what it varies.
- **judgement**: Name a test after the behaviour and its reason ("…, because both bylines print the number unconditionally"), since the title is where a reader of a failing run looks for the why.
- **hard**: Double a dependency at the seam the architecture declares: a stub layer for anything behind an Effect tag, MSW for a bare `fetch`, and a `vi.mock` of a vendor module that leaves the process only in the live layer's own co-located test ([ADR 0017](./docs/adr/0017-doubles-at-the-seam-the-architecture-declares.md)).
- **hard**: Test a loader by swapping `CmsClientLive` for the stub layer and keeping the real `fetchEntries`, because the runtime, the batching and the credential bail are what every loader relies on ([ADR 0016](./docs/adr/0016-vitest-resolves-astro-modules-itself.md)).
- **hard**: Undo in an `afterEach` (an `afterAll` for a change made once for the whole file) whatever a test changes outside itself (a stubbed global or environment variable, a spy, a faked clock, a node appended to the document), because a line at the end of a test body never runs once an assertion above it fails and the change leaks into every later test in the file. The rule holds where the tooling cannot see it too: a property assigned onto `window`, a controller whose signal a wiring listens on.
- **hard**: Pin the clock a case depends on (`vi.useFakeTimers({ toFake: ["Date"] })` and `vi.setSystemTime`, undone in an `afterEach`) and assert the exact instant or year it yields, because a bracket between two readings of the real clock passes whatever the code computed in between and a year read off it moves the expected value every January.
- **judgement**: Build a double as a factory that takes one `<Double>Params` object and returns what it recorded (`calls`, `inserted`, `sent`, `lines`), scoped to the test; `cmsLayer.ts` keeps module state and a reset because `vi.mock`'s factory reads it ([ADR 0017](./docs/adr/0017-doubles-at-the-seam-the-architecture-declares.md)).
- **judgement**: Assert the recorded `calls` whenever a double answers a wildcard host, because the wildcard answers a wrong request as readily as the right one ([ADR 0017](./docs/adr/0017-doubles-at-the-seam-the-architecture-declares.md)).
- **judgement**: Skip an end-to-end case that needs chrome `HIDE_CHROME` removes, with a reason naming what is missing, so the flag never turns a real failure into a pass ([ADR 0018](./docs/adr/0018-hide-chrome-replaces-the-page.md)).
- **hard**: Tag a case `@smoke` only for what proves the Worker answers on every deploy, never a result that depends on the caller's address, and keep the three cases every repository that deploys runs (a titled homepage, an unknown path answering 404, `robots.txt` served) word for word, because a failing smoke run rolls production back. What the served files say is the docs test's to assert.
- **hard**: Prove a new docs-test assertion by breaking the code it guards and watching it fail, permuting a pair rather than only renaming a token, because an assertion that never failed advertises coverage it lacks ([ADR 0015](./docs/adr/0015-docs-consistency-enforced-by-a-test.md)).
- **hard**: Guard every list a docs-test assertion derives from the repository (files, rows, matches) with a non-empty assertion or a synthetic self-test, because an assertion over an empty census passes whatever the tree holds ([ADR 0015](./docs/adr/0015-docs-consistency-enforced-by-a-test.md)).
- **hard**: Record a deliberate omission in the allowlist at the top of `docs/docs-consistency.test.ts`, and delete an allowlist that empties, because deleting the assertion is how that file stops being true ([ADR 0015](./docs/adr/0015-docs-consistency-enforced-by-a-test.md)).

## Workflows

- **hard**: Every `uses:` names a full commit SHA with its version in a trailing comment, or its branch for a pin that follows one, and the two move together: the SHA is what runs, the comment is the only thing that makes it legible, and Renovate maintains both halves.
- **hard**: YAML carries no explanatory comments; the reason for a line goes in the commit message, the pull request, an ADR or a rule here, and a gotcha an implementer would otherwise trip on goes in the *Gotchas* of [AGENTS.md](./AGENTS.md). The trailing comment on a SHA pin is the one exception.

## Docs

- **hard**: Keep `CONTEXT.md` to vocabulary: the term, one or two sentences on what it is, and the words it displaces, never how it is built, because mechanism belongs to the folder guide or an ADR.
- **hard**: State a rule once: a rule about how code is written here, a coupling or a gotcha in the guide of the folder it bites, a decision in an ADR; a wiki page says where the rule lives, because `docs/wiki/` is published and nothing checks a copy.
- **hard**: Write a guide in the present tense, holding what an implementer needs while working; the reason for a line goes in the commit message, the pull request, an ADR or a rule here, and history ("used to", "was", "until …") stays in git, because a guide is loaded into every session that works in its folder.
- **judgement**: Propose an ADR only for a decision that is hard to reverse, surprising without context and the result of a real trade-off, and link it from where it bites.
- **hard**: Delete a gotcha, an allowlist entry or a `docs/BACKLOG.md` item in the change that resolves it, because a stale entry is a false claim about the tree.

## Deliberate overrides of the smell baseline

- **Primitive Obsession**: a Slug and an ISO publish date stay plain strings. Each is minted at one boundary (`articleSlug`, `publishDateISO`) and `@const/routes.ts` alone turns a Slug into a path, so a brand would touch every schema and `reference()` for a guarantee the boundary already gives ([ADR 0019](./docs/adr/0019-three-questions-before-modelling.md)).
- **Data Clumps**: two functions whose parameters merely coincide each keep their own `<FunctionName>Params`, because the type is named after what takes it, and siblings that take the same input may share one named for that role, as `info`, `warn` and `error` share `LogParams` in `logging/logger.ts`.
- **Duplicated Code**: `logging/logger.ts` is byte for byte what the sibling repositories carry and `logging/contract.ts` differs from theirs only in `LOG_SERVICE`, so a change to either is made in all three ([ADR 0020](./docs/adr/0020-logs-and-traces-leave-through-cloudflares-export.md)).
- **Duplicated Code**: the stated-version helpers (`VERSIONED_DEPENDENCIES` through `declaredIn`) and the release-config helpers (`BREAKING_PARSER_OPTS` through `parserOptsOf`) in `docs/docs-consistency.test.ts` are byte for byte the same in biancafiore, contribKit and github-star-tracker, so a change to one is made in all three.
- **Duplicated Code**: the three smoke cases are word for word the same in every repository that deploys, so a difference between them is drift, not a variant.
- **Duplicated Code**: the Contact payload is validated at `defineAction`'s `input` and again in `validateContact`, because only the edge rejects an empty reCAPTCHA token and only the program is unit-testable; the `ManagedRuntime` behind `fetchEntries` and the per-request `ContactLayer` stay two runtimes ([ADR 0004](./docs/adr/0004-effect-for-infrastructure-clients.md)).
- **Middle Man**: `LoggerService` is a `Layer.sync` over the `logger` object, kept for the `R` signal that makes an unintended log a compile error ([ADR 0020](./docs/adr/0020-logs-and-traces-leave-through-cloudflares-export.md)).
- **Speculative Generality**: Effect tags and layers wrap the CMS, database and email clients although each has one consumer (`fetchEntries` for the CMS, the contact flow for the database and email), a heavy choice the ADR accepts ([ADR 0004](./docs/adr/0004-effect-for-infrastructure-clients.md)).
- **Shotgun Surgery**: a new content type edits its domain concept, its DTO, its loader, `src/content.config.ts` and `CONTEXT.md` together by design ([ADR 0012](./docs/adr/0012-pragmatic-ddd-domain-layer-anti-corruption-layer.md)); a new inverting or container-scaled component also edits its census line in the styles guide.
- **Mysterious Name**: `ASTRO_DB_REMOTE_URL` and `ASTRO_DB_APP_TOKEN` keep the Astro DB name, because renaming means re-provisioning the secrets ([ADR 0003](./docs/adr/0003-drizzle-libsql-turso-over-astro-db.md)); `HIDE_CHROME` keeps a name that understates it until the flag is deleted ([ADR 0018](./docs/adr/0018-hide-chrome-replaces-the-page.md)).
